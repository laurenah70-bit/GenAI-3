# 노코드 자동화 기초: 워크플로우 설계

Make, Zapier 등 노코드 자동화 도구를 사용해 Trigger–Action–조건분기(Router/Filter) 구조를 직접 구현한 과제 제출 저장소입니다.

## 저장소 구조

```
.
├── README.md                     ← 이 파일 (프로젝트 전체 개요)
├── project1/                     ← 프로젝트 1: 자동화 도구 비교 구현
│   ├── report.pdf                ← 비교 분석 보고서 (구성 화면·실행 결과·비교표 포함)
│   └── screenshots/              ← 개별 스크린샷 원본
│       ├── make_시나리오구성.png
│       ├── make_긴급알림.png
│       ├── make_일반알림.png
│       ├── zapier_zap구성.png
│       ├── zapier_구글시트데이터.png
│       ├── zapier_긴급알림.png
│       └── zapier_일반알림.png
└── project2/                     ← 프로젝트 2: 자유 주제 자동화 구현
    ├── report.pdf                ← 워크플로우 설계·구현·실행 결과 보고서
    └── screenshots/
        ├── make_시나리오구성.png
        ├── 구글캘린더_테스트일정.png
        ├── 슬랙_일정없음.png
        └── 슬랙_일정있음.png
```

각 프로젝트의 `report.pdf` 안에 스크린샷과 설명, 표가 모두 정리되어 있고, `screenshots/` 폴더에는 원본 이미지 파일을 개별적으로도 확인할 수 있도록 함께 올려두었습니다.

## 사용 도구

- **Make** (make.com) — 두 프로젝트 모두에서 사용
- **Zapier** (zapier.com) — 프로젝트 1에서 Make와 비교 대상으로 사용
- **Google Sheets**, **Google Calendar**, **Slack** — 연동 서비스

---

## 프로젝트 1: 자동화 도구 비교 구현 (Make vs Zapier)

### 개요
동일한 워크플로우를 Make와 Zapier 두 도구로 각각 구현하고 비교했다.

**워크플로우**: 구글 시트에 문의가 새로 접수되면 → 긴급도(긴급/보통) 조건에 따라 분기 → 서로 다른 슬랙 채널로 알림 발송

### 자동화 흐름
```
[Trigger] Google Sheets 신규 행 추가 감지
      ↓
[Router/Filter] 긴급도 열 값 확인
   ├─ "긴급" → Slack #긴급-알림 채널에 메시지 발송
   └─ "보통" → Slack #일반-알림 채널에 메시지 발송
```

- **Make**: `Google Sheets (Watch New Rows) → Router → Slack ×2`
- **Zapier**: 동일한 Trigger로 Zap을 2개 구성, 각각 `Filter by Zapier`로 긴급도 조건을 걸고 `Slack Send Channel Message` 연결 (무료 플랜 Paths 제약으로 인한 대안 구조)

### 실행 방법 (재현 방법)
1. 구글 시트에 `이름 | 문의내용 | 긴급도` 열 구성
2. Make/Zapier에 구글 계정, 슬랙 계정 연결
3. 시트에 긴급도="긴급" 또는 "보통"인 행을 입력하면 자동으로 해당 슬랙 채널에 메시지 발송

### 결과 확인 방법
`project1/report.pdf`에서 두 도구의 시나리오/Zap 구성 화면과, 긴급/보통 각 분기가 실제로 슬랙 메시지로 도착한 캡처를 확인할 수 있다. 6개 항목(UI/UX, 설정 난이도, 조건 분기 구현 방식, 연동 서비스 범위, 무료 플랜 범위, 실행 로그 확인 방식)에 대한 비교표와 장단점, 추천 상황도 함께 정리되어 있다.

## 프로젝트 2: 자유 주제 자동화 구현 (오늘 일정 브리핑)

### 반복 업무 정의
매일 아침 캘린더에 오늘 일정이 있는지 확인해 팀 채널에 공유하는 일을 자동화했다.

### 도구 선정 이유
Make — 프로젝트 1에서 Router(조건 분기) 사용법에 익숙해진 상태였고, 시간 기반 트리거와 캔버스 기반 구조 관리가 편리해서 선택했다.

### 자동화 흐름
```
[Trigger] Basic trigger + 매일 정해진 시각 스케줄
      ↓
[Action] Google Calendar Search Events (오늘 날짜 범위 검색)
      ↓
[Action] Array Aggregator (검색 결과를 배열로 집계, 0건이어도 다음 단계 보장)
      ↓
[Router] 배열 길이 조건으로 분기
   ├─ 일정있음 → Slack #오늘일정 채널에 "오늘 일정이 있습니다" 메시지
   └─ 일정없음 → Slack #오늘일정 채널에 "오늘은 일정이 없습니다" 메시지
```

### 실행 방법 (재현 방법)
1. Make에 Google Calendar, Slack 계정 연결
2. 시나리오 스케줄을 매일 원하는 시각(예: 오전 9시)으로 설정 후 ON
3. 매일 해당 시각에 자동 실행되어, 그날 일정 유무에 따라 슬랙에 알림 발송

### 결과 확인 방법
`project2/report.pdf`에서 Make 시나리오 전체 구성 화면, 테스트용 캘린더 일정 화면, 그리고 일정 있음/없음 두 분기가 각각 슬랙 메시지로 도착한 캡처를 확인할 수 있다.

## 배운 점 (Trigger / Action / 조건 분기)

- **Trigger**: 워크플로우가 시작되는 조건 (예: 시트에 새 행 추가, 정해진 시각 도달)
- **Action**: Trigger 이후 실제로 수행되는 동작 (예: 슬랙 메시지 발송)
- **조건 분기 (Router/Filter)**: 같은 Trigger라도 데이터 상태(긴급도, 일정 유무 등)에 따라 서로 다른 Action 경로로 나뉘도록 만드는 장치. 프로젝트 1과 2 모두에서 이 분기 로직이 실제로 두 경로 다 최소 1회 이상 실행되는 것을 캡처로 증명했다.
